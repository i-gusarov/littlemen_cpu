~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
         Instruction set                                               
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Definitions:
`res`      - First value from the priority result queue, if it has one.
             Otherwise first value from the data bus queue.
             Otherwise wait for a value to appear on the data bus.
             For even opcodes `res` is always 0.
             For each odd opcode `res` is evaluated only once,
             before any other effect of the opcode.
             The value is removed from the respective queue.

`post(x)`  - Post value `x` to the end of priority result queue.
             ALU always posts only to that queue.

`later(x)` - Post value `x` to the end of data bus queue.
             Only bus opcodes and virtual memory opcodes post to that queue.
             Bus devices may take several cycles to calculate the value
             and send it to the data bus.
             Posted value NEVER reaches the data processing core fast enough
             to be picked by the next op, it always arrives a few cycles later.
             If the next op needs `res`, it may pick the value from priority
             queue or block, see description of `res`.

`br(x, n)` - Send values `x` and `n` to the branching core.
             Value `x` will be used `n` times to decide
             which branch to take after the current code block.

Expressions shown as instruction effect are in C++ notation.
For example, "~" is bitwise NOT.
